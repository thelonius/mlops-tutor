# Lesson TF-1: Terraform state as source of truth — 2026-05-01

**Format:** case-lesson (scene → walkthrough → attention points → mental model → quiz)
**Duration:** ~one sitting
**Quiz score:** ~0.35

## What was taught
- State as TF's catalog of the real world; plan = diff(.tf, state)
- Local backend → infra swamp in teams (each engineer has their own state)
- Remote backend (S3 + DynamoDB) — shared state + locking
- backend.tf example with S3 bucket + DynamoDB lock table + encrypt
- What happens during apply: lock → fetch state → mutate cloud → update state → unlock
- Pitfalls: missing dynamodb_table = race; encrypt=false = secrets leak; Ctrl+C during apply = stuck lock

## Quiz answers

### Q1 (recall): two AWS services for remote backend?
**User answer:** named the example resource (Redis ElastiCache), not the backend
**Correct:** S3 (state file storage) + DynamoDB (lock table)
**Score:** 0.0 — misread question; answer was visible in lesson code

### Q2 (gotcha): plan no-changes, colleague applies, you plan again — what do you see?
**User answer:** "state has no colleague's changes if no remote backend"
**Correct:** depends on remote vs local backend; with S3 backend, TF refetches state each plan,
so you see new resource in state — if your local `.tf` is stale (no git pull),
plan shows "1 to destroy" (TF wants to align reality to your outdated code).
This is the classic "remote backend without CI gate" trap.
**Score:** 0.4 — got the underlying concept (state divergence), but framed as no-backend case

### Q3 (scenario): make TF "forget" a resource manually deleted in AWS console
**User answer:** "tf plan to see drift, then remove resource from state, then tf apply"
**Correct:** `terraform state rm <address>` — exact command; AND remove from .tf code,
otherwise next apply re-creates. apply at the end is wrong/redundant.
**Score:** 0.35 — workflow concept partial, command not named, post-step contradicts goal

## Mental model installed (target)
- state = TF's catalog of real world
- remote backend = catalog in shared place, accessible to team
- lock = while I apply, no one else can touch the catalog
- diff matrix: 6 combinations of (in .tf? / in state? / in cloud?) → predictable plan output
